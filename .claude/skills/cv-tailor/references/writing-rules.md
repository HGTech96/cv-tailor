# Writing Rules

These rules are absolute. A draft violating any of them is not done.

## Length

- Default: **1 page** for <7 years of experience, up to **2 pages** otherwise.
  Never exceed 2 pages.
- Max **8 bullets** for the current/most relevant role, max **5** for other
  recent relevant roles, max **3** for older or less relevant roles. These
  are ceilings, not targets — for candidates with fewer years of experience
  or thinner master-CV evidence, use fewer bullets rather than padding.
  Roles older than ~12 years: single line or omitted per profile.md.
- Summary paragraph allowed when it earns its space (career transitions,
  senior roles, or when the JD asks for a profile); max 3 lines. Skip it
  when the experience section already tells the story.

## Bullets

- Every bullet starts with a strong past-tense verb (present tense for current role).
- One line per bullet. If it wraps, cut it.
- Structure: **verb + what + measurable outcome or scale** where truthfully possible
  ("Reduced p95 API latency 40% by introducing request coalescing" — not "Responsible for API performance").
- No two bullets may start with the same verb within one role.
- Never state a metric that is not in the master CV. No rounding up.

## Language

- Banned words/phrases: spearheaded, leveraged, synergy, passionate, results-driven, dynamic, utilized (use "used"), responsible for, helped with, various, numerous, cutting-edge, world-class, detail-oriented, team player, go-getter.
- No first person ("I", "my").
- No filler adjectives; nouns and numbers carry the weight.
- Mirror the JD's exact terminology for skills when truthful (if JD says "Kubernetes", don't write "k8s").

## Sections

- Order and allowed sections come from `templates/cv-structure.md`.
- Skills section: single comma-separated line per category, max 3 categories, only skills evidenced somewhere in the CV body or master CV.
- No "References available on request", no photos, no age/marital status.
