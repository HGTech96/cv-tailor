# Profile — visibility rules & preferences

## Visibility rules
- Always include: the Criteo agentic troubleshooting assistant (LLM agent, Python/FastAPI, Azure OpenAI, GKE) — strongest and most current differentiator, should anchor every CV.
- Never include: teaching / Part-Time Lecturer role, unless the JD explicitly asks for mentoring, teaching, or training experience.
- Only if relevant: leadership/OKR/team-lead scope (feature-team lead, 6+ engineers, capacity planning) — include only when the JD asks for lead/management scope; otherwise keep the individual-contributor engineering work forward.
- Reference-only: fintech stint specifics (Steven/PEI Development — Mastercard/BankID/Swish/IBAN/Apple Pay integrations) and Synopsys semiconductor/yield-domain specifics (Bin/Wafer analysis, process nodes) — decide per job whether the underlying skills (full-stack delivery, Python automation, code-quality discovery) are worth surfacing without the domain jargon.

## Preferences
- Default CV length: follow writing-rules.md default (1 page for <7 years experience, up to 2 pages otherwise — no stricter override).
- Date format: "Mon YYYY" (e.g., "Sep 2022"), en dash for ranges (e.g., "Sep 2022 – Present"), matching master-cv.md.
- Region conventions: US-style — no photo, no age, no marital status; keep phone/location as-is since open to remote roles.
- Target roles: Senior Backend / Python Engineer (Django/FastAPI, REST APIs, PostgreSQL-backed systems); Contract / evaluative roles (AI-training, code review, technical assessment work).

## Standing notes
- When targeting evaluative/contract roles (AI-training, code review), emphasize code-quality judgment, architecture critique, and debugging/production-validation evidence over team-leadership scope.
- When targeting senior backend roles, lead with Python/Django/FastAPI backend depth, REST API design, and the LLM agent project as the standout initiative.
